Radboards Marketing Content System

A production-style Python project that will prepare marketing content for selected public Radboards products. This page is the handover reference before starting the caption-generation module.

Business: Radboards Website: radboards.in Implemented stages: foundation, database, catalogue scraper, image downloader, catalogue synchronization, campaign brief, marketing script

1. Current state

Completed and verified

The project foundation, local SQLite product tracker, focused Radboards catalogue scraper, controlled image downloader, catalogue-to-database synchronization, product understanding, and marketing-script generation are complete. Seventeen automated tests pass. The next module is caption generation.

Important scope rule

The system reads only five specified Radboards collections and will request no more than seven products from any one collection. Accessories, rentals, blogs, service pages, and all other site content are out of scope.

2. Project architecture

Radboards public catalogue→ Python scraper→ SQLite tracker→ Future AI/content workflow

Python

Handles deterministic tasks: public catalogue reading, database work, future image downloads, rendering helpers, and external API wrappers.

LangGraph (later)

Will handle product understanding, campaign briefs, scripts, captions, hashtags, creative direction, and feedback reasoning.

n8n (later)

Will handle business workflow: triggers, review, approval, notifications, uploads, and status updates.

3. Implemented database module

The database is a local SQLite file. It is created only when the application calls initialize_database(); no database file has to be committed to Git.

FileResponsibility
database/connection.pyOpens the configured SQLite file, turns on foreign-key checks, creates the products table, and closes connections safely.
database/repository.pyProvides add_product() and get_next_unprocessed_product(), keeping database queries out of other modules.
tests/test_repository.pyTests database creation, product insertion/retrieval, and duplicate URL prevention.

Products table

The table stores product_id, url, product_name, category, status, timestamps, last_processed_at, drive_link, and approval_status. New rows start as pending and not_reviewed.

6. How verification was performed

Tests use Python’s built-in unittest module; no extra testing dependency was added. The suite checks both modules without relying on live website data, then the scraper was also run read-only against the five live collections.

python -m unittest discover -s tests -v

Latest result: 17 tests passed. The live scraper returned the verified product counts listed above.

7. Two newly completed steps

Step 4: controlled image downloader

scraper/image_downloader.py accepts one ScrapedProduct and downloads at most five of its public product images into output/images/<product-handle>/. Existing files are reused, so a repeated run does not download or overwrite them. Generated images are excluded from Git.

Step 5: catalogue-to-database synchronization

scraper/catalog_sync.py reads only the five approved collections, adds their products to SQLite, preserves the product category, and skips URLs that already exist. This creates the bridge from public catalogue data to the local workflow queue.

Related tests are tests/test_image_downloader.py and tests/test_catalog_sync.py. The database migration adds the optional category column safely if an earlier local database already exists.

8. Two newly completed AI steps

Step 6: product understanding and campaign briefs

agents/product_understanding/campaign_brief.py turns a scraped product, optional local image paths, and approved brand context into a validated campaign brief. This brief is the single source of truth for later content agents.

Step 7: marketing-script generation

agents/script/marketing_script.py turns one campaign brief into a structured 15-to-45-second Instagram Reel script with a hook, voiceover, on-screen text, and call to action.

agents/gemini.py is the shared Gemini structured-output adapter. It uses GEMINI_API_KEY only for an intentional live AI run; the tests use local fake model responses, so no account or API key has been used. The editable brand context is docs/brand/radboards_brand_context.md.
